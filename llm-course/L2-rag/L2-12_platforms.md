# L2-12 · RAG 开源项目剖析：RAGFlow / FastGPT / Dify

> **所属阶段**：L2 RAG 开发实战工坊
> **本课目标**：深入理解三大主流 RAG 平台（RAGFlow / FastGPT / Dify）的定位、架构、数据模型与工作流，掌握选型方法与各自的核心实战路径。
> **先修**：L2-01 ~ L2-11。
> **预计时长**：90-120 分钟（含实验）

---

## 1. 为什么需要 RAG 平台

自研 RAG（L2-01~11）灵活但工程量大：文档解析、分块、索引、检索、评测、UI、权限、部署都要自己写。RAG 平台把这些封装成**可配置的产品**，让你用界面/配置完成 80% 的通用需求。

| 自研 | 平台 |
|---|---|
| 完全可控、可深度定制 | 开箱即用、运维简单 |
| 工程量大、周期长 | 灵活性受限 |
| 适合核心/差异化场景 | 适合通用知识库/快速落地 |

**结论**：先判断需求是否"通用"。通用 → 平台；差异化/核心 → 自研或平台+自研混合。

## 2. 三平台深度对比

### 2.1 定位

| 平台 | 定位 | 一句话 |
|---|---|---|
| **RAGFlow** | 深度文档理解 RAG 引擎 | "文档解析最强" |
| **FastGPT** | 知识库 + 可视化工作流 | "轻量易上手" |
| **Dify** | LLM 应用开发平台 | "全栈 + Agent" |

### 2.2 架构

**RAGFlow**
```
文档 → DeepDoc 深度解析（OCR/表格/布局）→ 模板化分块 → 向量化 → 知识库
     → 查询 → 混合检索 → 生成 → 引用溯源（可点击定位原文）
```
- 核心：`DeepDoc` 解析引擎、模板化分块（通用/论文/财报/合同/手册）
- 支持本地部署（Docker），支持多种向量库

**FastGPT**
```
知识库（QA 对 / 通用导入）→ 向量化 → 工作流（可视化节点编排）→ 应用发布（网页/API）
```
- 核心：知识库 + 工作流引擎 + 插件
- 工作流节点：搜索、LLM、问题分类、HTTP、代码、知识库引用等

**Dify**
```
数据集（RAG）+ 模型管理 + 工具/Agent + 工作流 + 应用 API
```
- 核心：RAG + Agent + 工作流统一编排；支持 Deep Research、数据库查询、工具调用
- 提供 SDK 与 API，可私有化部署

### 2.3 功能对比

| 维度 | RAGFlow | FastGPT | Dify |
|---|---|---|---|
| 文档解析 | ★★★（表格/扫描件强） | ★★ | ★★ |
| 工作流编排 | ★★ | ★★★ | ★★★ |
| Agent/工具 | ★ | ★★ | ★★★ |
| 部署方式 | Docker/本地 | Docker/云 | Docker/云/私有 |
| 上手难度 | 中 | 低 | 中 |
| 适合 | 复杂文档问答 | 知识库/客服 | 全栈 LLM 应用 |

## 3. 选型决策树

```
需求是否以"复杂文档"为核心（财报/合同/论文/扫描件）？
  ├─ 是 → RAGFlow
  └─ 否 → 是否需要 Agent/工具/多步编排？
           ├─ 是 → Dify
           └─ 否 → 是否追求快速搭知识库+工作流？
                    ├─ 是 → FastGPT
                    └─ 否 → 自研（L2-01~11）
```

**补充判断**：
- 团队无运维 → SaaS 版（FastGPT Cloud / Dify Cloud）
- 数据敏感 → 私有化部署（Dify / RAGFlow 本地）
- 需要深度定制检索 → 自研

## 4. 实战一：RAGFlow 构建 AI 医疗问诊助手

### 4.1 部署（Docker）
```bash
git clone https://github.com/infiniflow/ragflow
cd ragflow
docker compose up -d
# 访问 http://localhost
```

### 4.2 构建流程
1. **创建知识库**：上传医疗指南/药品说明书 PDF
2. **选择分块模板**：手册/论文/通用（对应 L2-02 分块策略）
3. **配置 embedding 与 reranker**（对应 L2-03/09）
4. **创建助手**：绑定知识库 + 设定 prompt（对应 L2-07 的"仅基于资料"约束）
5. **测试与调优**：用评测集验证（对应 L2-11）

### 4.3 医疗场景注意
- 引用必须可溯源到原文段落
- 对"无答案"问题要明确拒答
- 数字（剂量/频次）必须来自原文

---

## 5. 实战二：FastGPT 实时网页爬取 + RAG 发布

### 5.1 流程
1. **知识库**：导入网页 URL / 手动上传（FastGPT 支持网页抓取）
2. **工作流**：`用户输入 → 知识库检索 → LLM 生成 → 输出`
3. **发布**：生成网页链接或 API，嵌入业务系统

### 5.2 要点
- 网页抓取需处理动态渲染（部分平台支持）
- 定期更新知识库（对应 L2-01 "知识可更新"）
- 工作流可加"问题分类"节点做路由

---

## 6. 实战三：Dify 数据库智能查询 + 复刻 Deep Research

### 6.1 数据库智能查询
1. **工具**：配置 MySQL/Postgres 工具（连接 + SQL 执行）
2. **工作流/Agent**：`用户问题 → 生成 SQL → 执行 → 总结结果`
3. **安全**：只读账号、SQL 白名单、超时限制

### 6.2 复刻 OpenAI Deep Research
- **思路**：多轮检索 + 综合报告
- **实现**：Dify 工作流里编排"规划→多次检索→汇总→生成报告"
- **对应课程**：Multi-Query（L2-08）+ RAG-Fusion（L2-09）+ 长文生成

## 7. 通用文档智能问答系统商业化实战

### 7.1 通用架构（平台无关）
```
多源文档 → 解析 → 分块 → 索引 → 混合检索 → rerank → 生成（带引用）
```
### 7.2 商业化要点
- **多租户**：知识库/权限隔离
- **计费**：按 token / 按查询 / 按坐席
- **可观测**：查询日志、命中率、成本
- **合规**：数据脱敏、审计

### 7.3 与自研的映射
| 商业化能力 | 自研对应课程 |
|---|---|
| 文档解析 | L2-02 |
| 混合检索 | L2-06 |
| rerank | L2-09 |
| 评估 | L2-11 |
| 发布 | L2-13 |

## 10. 小结

- RAGFlow 强在文档解析；FastGPT 强在工作流与轻量；Dify 强在全栈 + Agent。
- 三者底层都是 RAG（L2-01~11），差异在工程封装与编排。
- 选型看：文档复杂度、是否需要 Agent/工作流、部署与运维成本。
- 平台不是银弹：复杂/差异化需求仍需自研能力。

## 11. 自测题

1. 为什么 RAGFlow 在复杂文档上表现更好？
2. FastGPT 的工作流与 Dify 的工作流有何异同？
3. 三平台各自底层 RAG 管线与本课 L2-01~11 的哪些环节对应？
4. 什么场景你会选自研而非用平台？
5. 用平台构建医疗助手时，必须做哪三件事？

### 自测题答案

1. **RAGFlow 文档解析强**：DeepDoc 支持 OCR、表格、多栏、扫描件，并做模板化分块与布局还原，减少 L2-07 的 P1/P2 问题。
2. **异同**：同——都是可视化节点编排（检索/LLM/条件/工具）；异——FastGPT 偏知识库+轻量流程，Dify 偏 Agent/工具/多步编排，节点能力更全。
3. **对应**：解析→L2-02；向量化→L2-03；检索→L2-04/06；rerank→L2-09；评估→L2-11；发布→L2-13。
4. **选自研的场景**：检索算法需深度定制、数据/合规特殊、需要极致成本优化、平台无法满足差异化需求。
5. **医疗助手三件事**：引用可溯源到原文、无答案时明确拒答、数字必须来自原文（防幻觉）。
