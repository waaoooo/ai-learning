## 1. 金融助手 RAG 实战

### 1.1 场景与数据

| 维度 | 内容 |
|---|---|
| **数据源** | 财报、研报、公告、法规、会议纪要（PDF/HTML/Word） |
| **查询类型** | 事实查询（营收/净利润）、合规检索、风险提示、对比分析 |
| **用户** | 分析师、合规、管理层 |
| **容错** | 极低：数字错一位就是事故 |

### 1.2 完整架构（串联 L2-08/09）

```
文档 → 加载/解析(表格专用) → 父子分块 → embedding
     → 混合检索(向量+BM25) → rerank(cross-encoder)
     → 上下文压缩 → LLM 生成(带引用) → 数字校验/门控 → 输出
```

| 环节 | 技术选择 | 对应课程 |
|---|---|---|
| 解析 | PyMuPDF / Unstructured，表格单独抽取 | L2-02 / L2-07 P1 |
| 分块 | 父子索引（child 检索、parent 生成） | L2-08 |
| 检索 | 向量 + BM25 混合 | L2-06 |
| 重排 | cross-encoder reranker | L2-09 |
| 生成 | 严格 prompt + 结构化输出 | L2-13 |
| 评估 | Faithfulness + 数字准确率 | L2-11 |

### 1.3 数字保真（金融的生命线）

金融答案中"120 亿"写成"12 亿"或"1200 亿"都是事故。工程化保证：

1. **Prompt 约束**："所有数字必须逐字来自资料，禁止换算/推算"
2. **输出后校验**：正则提取答案中的数字，与检索上下文比对，缺失则拒绝输出
3. **引用绑定**：答案中每个数字后标注来源 chunk 名
4. **置信度门控**：无高相关 chunk 时拒答（"资料不足"）
5. **禁用模型做数学**：比例/增长率让模型从原文抄，或单独用计算器工具

```python
import re
def validate_numbers(answer, contexts):
    nums = set(re.findall(r"\d+(?:\.\d+)?", answer))
    src = set(re.findall(r"\d+(?:\.\d+)?", "".join(contexts)))
    missing = nums - src
    return missing  # 非空则答案含未溯源数字，需拦截
```

### 1.4 时效性处理
- **元数据**：每份文档带 `publish_date`
- **过滤**：只检索近 N 年（或用户指定区间）
- **加权**：时间越新权重越高（`score += α * recency`）

### 1.5 表格解析
- 财报表格是数字密集的雷区；普通文本切分会把表格拆散
- 方案：单独抽取表格 → 转 Markdown/结构化 → 独立 chunk + 表头 metadata

## 2. 多模态 RAG 深入

### 2.1 三种方式原理

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **① 图像转文本（caption）** | VLM 把图片转文字描述 → 纳入文本 RAG | 简单、复用文本管线 | 丢失视觉细节，依赖 caption 质量 |
| **② 多模态 embedding** | CLIP/Chinese-CLIP 同时编码图与文 → 统一向量空间 | 真正跨模态检索 | 需多模态模型、部署贵 |
| **③ 双索引 + 融合** | 图像索引 + 文本索引分别建，检索后 RRF 融合 | 灵活、可解释 | 实现复杂、需对齐两路 |

### 2.2 成本 / 精度排序

- **成本**：① < ③ < ②（caption 只需一次 VLM；双索引要维护两套；CLIP 需要专门模型）
- **精度（视觉细节）**：② > ③ > ①（CLIP 保留视觉语义；caption 丢失细节）

### 2.3 选型

- **原型/图文混排文档**：①（把图注、caption 纳入索引）
- **以文搜图/以图搜图、设计素材**：②（CLIP）
- **既要文本问答又要图像召回**：③

### 2.4 实现要点
- **caption**：用 VLM 生成"描述 + 结构化字段"（图表类型、坐标轴、关键数值）
- **CLIP**：文本与图像归一化到同一向量空间，用 cosine；注意中文用 Chinese-CLIP
- **双索引融合**：RRF（L2-09）对齐两路排名，无需同尺度分数

## 3. 多模态评估

- **检索层**：图文匹配的 Recall@k / Precision@k（人工标注相关图）
- **响应层**：答案是否引用了正确的图/表
- **特有指标**：caption 质量（人工/自动）、视觉细节保留率

## 6. 小结

- 金融 RAG = Advanced RAG 全链路 + **数字保真 + 时效 + 合规**。
- 多模态 RAG 三方式：caption（①）、多模态 embedding（②）、双索引融合（③）；成本①<③<②，精度②>③>①。
- 图文检索难点在"对齐"与"保留视觉信息"。

## 7. 自测题

1. 金融 RAG 中"数字必须来自原文"如何工程化保证？
2. 三种多模态方式的成本/精度排序？
3. 方式①中 caption 质量差会怎样？如何缓解？
4. 双索引融合时，图像和文本的 rank 如何对齐？

### 自测题答案

1. **数字保真**：prompt 强约束 + 输出后正则校验（数字须出现在上下文）+ 引用绑定 + 置信度门控 + 禁用模型做数学。
2. **排序**：成本①<③<②；视觉精度②>③>①。
3. **caption 差**：检索噪声增大、召回错误；缓解：多模型/人工复核 caption、结构化字段抽取、结合图像标签。
4. **对齐**：用 RRF 等基于排名的融合（无需同尺度分数），或分别归一化后加权。
