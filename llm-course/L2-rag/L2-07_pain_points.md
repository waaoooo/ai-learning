# L2-07 · 商业化 RAG 痛点分析

> **所属阶段**：L2 RAG 开发实战工坊
> **本课目标**：系统梳理 RAG 在商业化落地中的常见痛点，建立问题诊断框架，为 L2-08 Advanced RAG 的优化方案做铺垫。
> **先修**：L2-01 ~ L2-06（Naive RAG 全链路 + 混合检索）。
> **预计时长**：45-60 分钟

---

## 1. 从 Naive 到商业化：差距在哪

Naive RAG 在 demo 中跑得通，但上线后常出现：答非所问、幻觉、引用错误、延迟高、成本高。本课把问题归类为 9 类痛点，每类给出"症状 → 根因 → 解决方向"。

---

## 2. 九大痛点

### P1. 文档加载准确性和效率
- **症状**：PDF 表格错乱、多栏串行、扫描件无文本、加载慢
- **根因**：加载器对复杂布局支持差；OCR 质量低
- **方向**：PyMuPDF / Unstructured / LlamaParse；表格单独抽取；异步批量加载

### P2. 文档切分粒度
- **症状**：答案被切断 / 上下文冗余 / 检索噪声大
- **根因**：chunk_size 不匹配内容；固定切分破坏语义
- **方向**：递归/结构化/语义分块；父子索引（L2-08）

### P3. 错排：相关文档排名靠前的却是噪声
- **症状**：top-1 不是最佳；相关文档排在后面
- **根因**：embedding 语义相似 ≠ 任务相关；查询与文档表述差异
- **方向**：reranker（cross-encoder）重排序（L2-09）

### P4. 提取上下文与答案无关
- **症状**：检索到的 chunk 跟问题沾边但不含答案
- **根因**：召回粒度粗；查询表述与文档不匹配
- **方向**：查询改写、HyDE、多路召回、父子索引

### P5. 格式错误
- **症状**：LLM 输出格式不符合要求（JSON 解析失败、字段缺失）
- **根因**：prompt 约束不足；模型能力限制
- **方向**：结构化输出（JSON mode / function calling）、few-shot 示例、校验重试

### P6. 答案不完整
- **症状**：只答了部分，漏掉关键信息
- **根因**：top-k 太小；上下文窗口截断；prompt 未要求完整
- **方向**：增大 k + rerank；Map-Reduce；要求"完整回答"

### P7. 未提取到答案
- **症状**：资料中有答案但 LLM 说不知道
- **根因**：检索未召回；或 chunk 中答案被稀释
- **方向**：提高召回（混合检索）；更小粒度 chunk；查询扩展

### P8. 答案太具体或太笼统
- **症状**：过度细节或过度抽象
- **根因**：prompt 未指定粒度；检索上下文粒度不匹配
- **方向**：prompt 明确粒度；多粒度索引

### P9. 幻觉问题
- **症状**：编造事实、引用不存在的来源
- **根因**：上下文不足时模型"补全"；prompt 约束弱
- **方向**：严格"仅基于资料"；引用校验；置信度门控；RAG 评估（L2-11）

## 3. 诊断框架

遇到问题时按链路定位：

```
加载 → 分块 → embedding → 索引 → 检索 → prompt → 生成
  ↑       ↑       ↑       ↑       ↑       ↑       ↑
  P1      P2      P3/P4   P3     P3/P4/P7  P5/P8   P6/P9
```

**实践**：记录每次查询的检索 chunks + 分数 + 最终答案，做 error analysis。

## 5. 小结

- 商业化 RAG 的问题多来自链路各环节；先诊断再优化。
- 9 类痛点对应 Advanced RAG 的优化技术（L2-08~L2-09）。
- 建立评测集 + error analysis 是持续改进的基础（L2-11）。
