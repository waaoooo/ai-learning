## 1. 为什么需要混合检索

- **向量检索**：语义理解强，能匹配"高血压"↔"血压升高"，但对精确术语/缩写/编号弱
- **关键词检索（BM25）**：精确匹配术语、编号、专有名词，但无语义
- **混合**：两者互补，显著提升召回率与准确率

**医疗场景尤其需要**：疾病名、药品名、ICD 编码等精确术语 + 症状描述的语义。

---

## 2. BM25 原理

BM25 是经典关键词检索排序函数：

```
score(q, d) = Σ_{t in q} IDF(t) * (tf(t,d)*(k1+1)) / (tf(t,d) + k1*(1 - b + b*|d|/avgdl))
```

| 符号 | 含义 |
|---|---|
| `tf` | 词在文档中的频率 |
| `IDF` | 逆文档频率，罕见词权重高 |
| `k1`（~1.5） | 词频饱和速度 |
| `b`（~0.75） | 文档长度归一化强度 |

- 中文需分词；本课用**字符级 n-gram 近似**（生产用 jieba/HanLP）
- BM25 对"词面精确匹配"敏感，对"语义改写"无感

---

## 3. 融合策略

| 策略 | 公式/做法 | 特点 |
|---|---|---|
| **加权分数融合** | `score = α·norm(vec) + (1-α)·norm(bm25)` | 需归一化；α 控制语义/关键词倾向 |
| **RRF** | `score = Σ 1/(k + rank_i)` | 无需归一化，鲁棒，**推荐默认** |
| **两阶段** | BM25 粗召回 + 向量 rerank（或反之） | 工程上常见 |

### 3.1 加权融合
- α=0.9 → 偏语义，适合开放问答/同义改写多
- α=0.3 → 偏关键词，适合术语/编号/精确匹配（法律/医疗/代码）

### 3.2 RRF
- 只用**排名**，天然融合不同尺度分数
- k 小（10）→ 头部差异放大；k 大（60）→ 更平滑

### 3.3 归一化方法（加权融合前提）
向量分数与 BM25 分数尺度不同，必须先归一化：
- **min-max**：`(x - min) / (max - min)`，简单但对异常值敏感
- **z-score**：`(x - mean) / std`，适合分数分布近似高斯
- **rank 归一化**：用排名 / 总数，鲁棒
> 不推荐直接用原始分数加权——向量相似度常在 0~1，BM25 可能到 10+，会一边倒。

### 3.4 两阶段融合
```
阶段1：BM25 粗召回 top-50（快、精确）
阶段2：向量 rerank 或 cross-encoder rerank（慢、准）
```
- 工程上更可控：先保证召回，再优化排序
- 与 RRF 可组合：BM25 粗召回 + 向量补充 + rerank

## 4. 混合检索效果评估

- **离线**：对标注集算 Recall@k / Precision@k / MRR，对比纯向量 vs 纯 BM25 vs 混合
- **在线**：观察 top-3 命中率、用户反馈
- **经验**：医疗/法律/代码场景混合通常比单路高 10-30% 召回

---

## 5. 常见坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 未归一化就加权 | 一边倒（BM25 压过向量） | 先归一化或改用 RRF |
| 中文未分词 | BM25 退化为字符匹配，噪声大 | jieba/HanLP 分词 |
| k 过大 | 头部差异被抹平，强匹配被稀释 | 先用 k=10~20 |
| 缩写/别名 | 精确匹配失败 | 同义词表 + 查询扩展 |
| 两路召回数量不等 | 融合偏向数量多的一路 | 固定各自 top-k 或按 rank 融合 |

## 6. 小结

- 混合检索 = 语义 + 关键词，互补；医疗/法律/代码场景收益明显。
- RRF 融合简单鲁棒，推荐默认；加权融合需归一化。
- 中文分词质量影响 BM25；生产用专业分词器。

## 7. 自测题

1. 什么场景下纯向量检索会失败？纯 BM25 会失败？
2. RRF 为什么不需要分数归一化？
3. α（向量权重）设为 0.9 vs 0.3，分别适合什么场景？
4. 医疗实体命名中，"缩写/别名"问题如何解决？

### 自测题答案

1. **失败场景**：纯向量在精确术语/缩写/编号/罕见词匹配上弱；纯 BM25 在同义改写、语义相似但词面不同、跨语言上弱。
2. **RRF 无需归一化**：只用排名（rank）而非原始分数，`1/(k+rank)` 无量纲，天然可融合不同尺度分数。
3. **α 选择**：0.9 偏语义，适合开放问答/同义改写多；0.3 偏关键词，适合术语/编号/精确匹配（法律/医疗/代码）。
4. **缩写/别名**：同义词表/别名词典、查询扩展（把缩写展开）、实体链接（entity linking）。

## 附录：FAQ

**Q：混合检索一定比单路好吗？**
A：通常更好（互补），但若语料极小或查询极规范，收益有限；用评测集验证。

**Q：RRF 和加权融合怎么选？**
A：RRF 无需归一化、鲁棒，默认首选；加权融合可精细控制语义/关键词比例，但需归一化。

**Q：中文 BM25 一定要分词吗？**
A：生产建议分词（jieba/HanLP）；字符 n-gram 只是无依赖时的近似。

**Q：BM25 能直接做语义检索吗？**
A：不能。BM25 只看词面，语义改写靠向量。

**Q：混合检索后还要 rerank 吗？**
A：要。混合解决"召回覆盖"，rerank 解决"top 排序精度"，两者互补。
