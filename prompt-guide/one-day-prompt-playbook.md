# 一天学会并应用提示工程（企业版）

## 核心认知（先读这段，2 分钟）

**目标不是"背下来"，而是"能用"。**  
记忆 = 外部速查表 + 内化 5 条核心 + 真实练习。  
一天 = 理解最小核心 → 立即应用 → 建立速查索引。

---

## 上午（9:00-12:00）：最小核心 + 第一个应用

### 9:00-9:30 理解最小核心（只记 5 条）
1. 三铁律：具体 / 说要做什么 / 分解
2. 参数：temperature↔top_p 二选一
3. 技术选型：Zero-shot / CoT / RAG / ReAct（4 个）
4. Agent 三组件：规划+工具+记忆
5. 反模式：模糊指令 / 盲目CoT / 示例偏斜

### 9:30-10:30 写第一个真实 prompt
选一个你手头的真实任务（如"写产品描述"或"分类工单"），按模板写：
```
你是 [角色]。任务：[具体任务]。
约束：[必须做] [禁止做]
输出格式：[JSON/列表/段落]
```
→ 立即用 LLM 测试 → 记录结果与失败点。

### 10:30-12:00 迭代 + 评估
- 根据失败点调整（每次只改一个变量）
- 建立 5-10 条测试样本，量化准确率/格式遵循率
- 记录：基线 vs 优化后

---

## 下午（14:00-17:00）：三场景实战

### 14:00-15:00 场景 A：推理任务
用 CoT 解决一个数学/逻辑题，对比 Zero-shot vs CoT 的准确率。

### 15:00-16:00 场景 B：知识问答
用 RAG（或"提供文档+要求引用来源"）回答一个事实性问题，检查幻觉率。

### 16:00-17:00 场景 C：Agent/工具
设计一个 ReAct 流程：搜索 → 计算 → 回答，记录工具调用序列与失败点。

---

## 晚上（19:00-21:00）：内化 + 索引

### 19:00-19:30 闭卷自测（5 分钟）
默写 5 条最小核心 + 技术选型 4 个。错的只重读那一行。

### 19:30-20:30 建立速查索引
- 把速查表打印/贴在显示器旁
- 在笔记里建"问题→技术"映射表（如"需要外部信息→RAG/ReAct"）
- 保存今天写的所有 prompt 到一个文件（版本化）

### 20:30-21:00 总结
写 3 句话：
1. 今天学会了什么？
2. 哪个技术最有用？
3. 下次改进什么？

---

## 一天结束的验收标准
- [ ] 能闭眼写出 5 条最小核心
- [ ] 完成 1 个真实 prompt 的迭代+评估
- [ ] 完成 3 个场景练习
- [ ] 建立速查索引 + 版本化 prompt

## 关键心态
- **不要背诵，要应用**。应用一次胜过重读十遍。
- **速查表是你的外部大脑**，不必内化全部，但要知道"何时查什么"。
- **错的不可怕**，每次失败都是一个知识缺口，只补那一块。
